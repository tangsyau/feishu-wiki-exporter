# 离线知识库设计

## 产品分工

“飞书知识库导出助手”面向知识库管理员，负责飞书授权、下载、增量更新以及生成离线知识库。

“飞书知识库离线阅读器 / Feishu Wiki Reader”面向普通阅读者，不需要 App ID、App Secret 或飞书账号，只读取管理员生成的知识库目录。

## 数据格式

当前离线知识库格式为 `feishu-offline-knowledge` version 2，采用只读、跨平台的目录结构。新版 Reader 同时兼容 version 1：

| 路径 | 内容 |
|---|---|
| `manifest.json` | 格式版本、知识库名称、生成时间以及文档标题、类型、面包屑和原文件路径 |
| `tree.json` | Reader 使用的页面语义树；页面可以同时包含正文标识和子页面 |
| `pages/*.json` | DOCX 转换得到的阅读 HTML 和可搜索纯文本 |
| `index/search-index.json` | 预先生成的倒排索引 |
| `files/` | 原始导出文件及其目录层级 |

阅读器程序和知识库数据相互独立。管理员更新知识库时，只需重新生成并分发知识库目录，不需要重新编译 Reader。

导出器会把飞书节点 Token、父节点 Token、同级顺序、标题及导出路径保存在原始导出目录的 `.feishu-export/order.json` version 2 中。生成离线知识库时，这些信息被转换为 `tree.json` 页面树，但不会给实际文件名添加序号。

页面树不再把知识库强制拆成“文件夹”和“文档”：有正文且有子页面的节点同时包含 `documentId` 和 `children`；纯导航页的 `documentId` 为 `null`，但仍保留 `children`。缺少新版层级元数据或读取到旧版 `order.json` version 1 时，生成器仍按原文件目录和同级顺序生成兼容树。

## 增量生成

再次生成同一离线知识库时，生成器会比较源文件大小和修改时间。未变化的 DOCX 直接复用已有网页页面，只有发生变化的 DOCX 重新转换。搜索索引根据当前页面重新建立，避免文档删除或移动后留下旧索引。

只调整飞书节点顺序而不修改正文时，Exporter 可以继续跳过未变化文件；新生成的 `tree.json` 仍会采用最新顺序。

## 搜索

中文、日文假名和韩文文本使用相邻二元组生成索引，英文和数字按连续单词建立索引。搜索先显示标题命中的结果，再显示标题未命中但正文命中的结果；同组内继续按完整短语等匹配程度排序。以空格分开的多个关键词如果都出现在标题中，也归入标题命中组。

Reader 只加载候选文档的正文文本来生成摘要，不会在每次查询时重新遍历全部 DOCX。从结果打开文档后，可以返回原结果列表并恢复搜索关键词和滚动位置。

正文全文索引当前只覆盖可成功转换的 DOCX。PDF、XLSX 和其他附件可以按标题找到并打开原文件，但不解析正文，也不执行 OCR。

## DOCX 转换范围

转换器直接读取 WordprocessingML，不依赖 Word、LibreOffice、Pandoc 或商业 Office 组件。当前处理常见段落、Heading/outline 标题、粗体、斜体、下划线、简化列表、表格、HTTP(S) 链接和 DOCX 内嵌图片。

转换目标是生成易读的知识库页面，而不是像 Word 一样像素级还原版式。复杂浮动布局、特殊域、嵌入对象和部分高级格式可能被简化或忽略。

## Web 部署预留

当前不提供内网服务器部署流程。前端已将数据访问封装为 `KnowledgeProvider`：Tauri 版读取用户选择的本地知识库目录；普通 Web 模式预留从 `./knowledge/` 读取相同 JSON 和文件结构的 provider。

如果以后改为静态内网站点，主要工作将集中在部署、身份验证和访问控制，不需要重写阅读界面或搜索索引格式。
