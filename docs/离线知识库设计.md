# 离线知识库设计

## 产品分工

“飞书知识库导出助手”面向管理员，负责飞书授权、读取页面、下载资源、增量更新以及生成离线知识库。

“飞书知识库离线阅读器 / Feishu Wiki Reader”面向普通阅读者，不需要 App ID、App Secret 或飞书账号，只读取管理员分发的知识库目录。Reader 程序与知识库数据相互独立；更新内容时不需要重新编译或重新安装 Reader。

## 输出模式

Exporter 0.2.0 提供三种模式：

| 模式 | 输出 |
|---|---|
| Reader 离线包 | 默认，只生成 `<知识库名>-offline` |
| Office 文档 | 只生成 DOCX、PDF、XLSX 和附件 |
| Reader + Office | 一次读取飞书，同时生成两种结果 |

Reader 模式不创建临时 DOCX。选择“两者”时，目录树和文档块只请求一次，再分别交给 Reader 生成器和 Office 导出器。

## version 3 数据格式

当前格式为 `feishu-offline-knowledge` version 3。Reader 同时兼容 version 1 和 version 2。

```text
<知识库名>-offline/
├─ manifest.json
├─ tree.json
├─ pages/
│  └─ <pageId>.json
├─ index/
│  └─ search-index.json
├─ diagnostics/
│  └─ unsupported-blocks.json
├─ assets/
│  ├─ images/
│  ├─ attachments/
│  └─ files/
└─ README.txt
```

| 路径 | 内容 |
|---|---|
| `manifest.json` | 格式版本、知识库名称、生成时间、统计信息以及页面元数据 |
| `tree.json` | 飞书页面语义树；同一节点可以同时具有 `documentId` 和 `children` |
| `pages/*.json` | 规范化块、可搜索纯文本和未支持块数量 |
| `index/search-index.json` | 中文相邻二元组及英文单词倒排索引 |
| `diagnostics/unsupported-blocks.json` | 未支持块所在页面、块 ID 和飞书类型 |
| `assets/images/` | Reader 页面显示所需图片 |
| `assets/attachments/` | 文档内嵌 PDF 等附件 |
| `assets/files/` | Reader 无法直接呈现、需要交给系统程序打开的文件 |

version 3 不包含整套 Office 文件，也不重复保存可由块数据呈现的正文 DOCX。

## 页面模型

Reader 忠实采用飞书“所有节点都是页面，页面可以拥有子页面”的模型：

- 每个飞书页面都有稳定的离线 `pageId`；
- 点击树中的标题打开页面；
- 点击展开箭头显示子页面；
- 纯导航页和有正文的父页面都完整保留；
- Reader 不执行导航页判定，也不读取 Office 跳过清单；
- 导航页判断只决定 Office 导出是否生成对应文件。

子页面目录块转换为 Reader 内部页面链接。正文中的飞书页面提及和可识别的飞书链接也转换成内部链接；页面目录转换成本页标题锚点。链接使用 `pageId`，因此移动整个离线包后仍然有效。

如果飞书的子页面目录块没有返回具体目标，生成器使用已读取的父子关系重建可点击子页面列表。同一页面存在多个无法区分范围的目录块时，只在第一个目录位置生成一次完整子页面列表，避免重复内容。

## 块规范化

第一版 version 3 重点处理普通段落、多级标题、有序和无序列表、任务列表、引用、代码、分隔线、提示块、图片、附件、基础表格、页面目录和子页面目录。每个块独立保存，因此段落、标题和子页面条目不会再被拼接在一起。

无法识别的块不会静默删除。页面 JSON 保留其飞书块类型，Reader 显示“暂不支持的内容块”，`manifest.json` 同时记录总数，便于后续根据实际样本扩展。

## 搜索

搜索索引直接从规范化块文本生成，不再读取 DOCX。块之间写入明确换行；子页面标题可以搜索，但子页面正文不会重复计入父页面。

中文、日文假名和韩文使用相邻二元组，英文和数字按连续单词建立索引。结果严格先显示标题命中，再显示只命中正文的页面；同组内按完整短语等匹配程度排序。从结果打开页面后，可以返回原结果列表并恢复搜索词与滚动位置。

PDF、XLSX 和其他附件目前只按标题搜索，不解析正文，也不执行 OCR。

## 增量状态

状态保存在用户选择的导出根目录，而不是某一种输出目录：

```text
.feishu-exporter-state/
└─ <来源哈希>/
   ├─ source.json
   ├─ reader-state.json
   ├─ office-state.json
   ├─ order.json
   ├─ navigation-analysis.json
   ├─ page-cache/
   └─ asset-cache/
```

来源哈希由来源类型和知识库 ID / Folder Token 计算，不包含 App Secret。Reader 与 Office 状态相互独立；删除输出目录后，页面和资源缓存仍可用于重新生成。首次使用 0.2.0 时，如果新版 Office 状态尚不存在，程序会复制旧版 `.feishu-export/state.json`，但不会删除旧文件。

页面内容未修改且子页面结构未变化时，可复用 `page-cache`。只调整节点顺序时，新的 `tree.json` 仍使用当前飞书顺序；如果某页面中的子页面目录受此变化影响，则结构签名会使该页面重新生成。

## Web 部署预留

当前不提供内网服务器部署流程。前端仍通过 `KnowledgeProvider` 访问数据：Tauri 版使用受限本地文件接口，Web 模式从 `./knowledge/` 读取同样的 manifest、页面、索引和资源结构。

未来部署静态内网站点时，主要新增部署、身份验证和访问控制，不需要重写知识树、页面渲染或搜索格式。
