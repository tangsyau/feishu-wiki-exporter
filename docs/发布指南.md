# 发布指南

本文面向项目维护者，说明如何为 Exporter 和 Reader 发布同一版本。普通用户只需在程序界面中查看当前版本，并与 GitHub Releases 中的最新版比较。

## 版本来源

仓库根目录的 `VERSION` 是项目版本号的唯一来源。当前采用语义化版本：

- 修复错误且保持兼容：递增修订号，例如 `0.1.0` → `0.1.1`；
- 增加功能或产生值得说明的行为变化：递增次版本号，例如 `0.1.1` → `0.2.0`；
- 功能与数据格式稳定并作出正式兼容承诺：发布 `1.0.0`。

.NET 构建会直接读取 `VERSION`。Reader 的 npm、Rust、Tauri 和 Linux AppStream 元数据也需要相同版本，项目脚本负责同步这些字段。

## 准备新版本

在仓库根目录运行：

```bash
node scripts/set-version.mjs 0.1.1
node scripts/check-version.mjs
```

随后更新 `CHANGELOG.md`，只记录用户能够感知的重要新增、变更、修复和兼容性说明，不记录内部讨论或逐次提交过程。

提交并推送：

```bash
git add .
git commit -m "Release 0.1.1"
git push origin main
```

## 自动创建 GitHub Release

确认 `main` 分支的 `build` 和 `reader` 工作流通过后，在本地为同一提交创建并推送标签：

```bash
git tag -a v0.1.1 -m "Release 0.1.1"
git push origin v0.1.1
```

标签会触发统一的 `release` workflow：

1. 调用可复用的 `build` workflow，编译并封装全部 Exporter 平台；
2. 调用可复用的 `reader` workflow，编译全部 Reader 平台；
3. 调用 WebKitGTK 4.0 兼容版工作流，并汇总 17 个最终安装包和 Portable 包，不保留 Actions 下载时的外层 ZIP；
4. 将 Reader 的 Windows 文件夹封装为 Portable ZIP；
5. 统一 Reader 的发布文件名，并生成 `SHA256SUMS.txt`；
6. 从 `CHANGELOG.md` 自动提取当前版本说明；
7. 创建并上传到一个尚未公开的 Draft Release。

工作流完成后，打开仓库的 **Releases** 页面，检查对应草稿中的版本说明、17 个软件包和 `SHA256SUMS.txt`。确认无误后点击 **Publish release**；无需手动下载或重新上传 Actions 产物。

Actions 会校验 Git 标签与 `VERSION`：如果标签为 `v0.1.1`，而源码仍是 `0.1.0`，构建会直接失败。若重新运行工作流，自动化只会更新尚未发布的草稿；已经公开的 Release 不会被覆盖。

`release` 任务仅使用 GitHub 自动提供的短期 `GITHUB_TOKEN`，并只为最后的草稿创建任务授予 `contents: write`。不需要创建或保存个人访问令牌。

## 发布文件命名

Exporter 使用以下形式：

```text
feishu-wiki-exporter-0.3.1-win-x64.zip
feishu-wiki-exporter-0.3.1-linux-x64.AppImage
feishu-wiki-exporter-0.3.1-linux-x64-portable.tar.gz
```

Reader 的 Release 文件使用以下形式：

```text
feishu-wiki-reader-0.3.1-windows-x64-portable.zip
feishu-wiki-reader-0.3.1-linux-x64-webkitgtk4.1.rpm
feishu-wiki-reader-0.3.1-linux-arm64-webkitgtk4.1.deb
feishu-wiki-reader-0.3.1-linux-x64-webkitgtk4.0.AppImage
```

## 发布前验证

创建 Release 前应完成[发布前测试清单](发布前测试清单.md)，尤其确认：

- Exporter 与 Reader 界面显示相同版本；
- Windows 文件属性和 Linux 软件包元数据版本正确；
- 文件名、`VERSION`、Git 标签和 Draft Release 标题一致；
- `CHANGELOG.md` 已包含该版本的用户可见变化。
