# 发布前测试清单

本文面向项目维护者和测试者，用于在发布 Exporter 与 Reader 二进制包前进行跨平台验证。

## 自动化构建

- `node scripts/check-version.mjs` 确认所有项目元数据与根目录 `VERSION` 一致；
- `build` workflow 完成还原、编译和单元测试；
- `reader` workflow 完成 Web 前端构建和 Tauri 桌面打包；
- Exporter Actions 共生成 8 个产物：2 个 Windows、4 个常规 Linux、2 个 Alpine Linux；
- Reader Actions 生成 Windows x64 Portable ZIP，以及 Linux x64 / ARM64 的 AppImage、DEB 和 RPM；
- 所有正式发布包均包含 `LICENSE`、`NOTICE` 和相应的第三方字体许可证。
- 推送版本标签后，`release` workflow 自动汇总 15 个软件包并创建 Draft Release；
- Draft Release 包含 `SHA256SUMS.txt`，且其中列出的文件与实际附件一一对应。

## 版本信息

- Exporter 和 Reader 界面均显示本次发布版本；
- Windows Exporter 文件属性中的产品版本、文件版本与 `VERSION` 一致；
- Reader 的 DEB、RPM 和 AppImage 元数据版本与 `VERSION` 一致；
- Actions 产物名包含版本、平台和架构；
- Git 标签采用 `v<版本>`，并与 `VERSION` 和 GitHub Release 标题一致；
- `CHANGELOG.md` 已记录本次发布的用户可见变化。
- 自动生成的 Draft Release 说明与 `CHANGELOG.md` 当前版本内容一致。

## Exporter 界面

- 窗口标题和侧栏中文名显示“飞书知识库导出助手”，副标题显示“Feishu Wiki Exporter”；
- 默认窗口尺寸下三个步骤、底部按钮和说明文字完整显示；
- 最小窗口 840×540 下三个页面均可滚动访问，控件没有重叠或截断；
- Windows 分别在 100%、125%、150%、200% 缩放下检查文字、边框和按钮；
- Linux HiDPI 下检查内置 Noto Sans SC、应用图标和进度条；
- 导出期间不能切换步骤，取消、进度和日志正常工作；
- 导出成功后主按钮显示“再次导出”，取消后显示“继续导出”，失败后显示“重新导出”；
- 成功读取知识库列表后，手动 ID 输入默认收起；列表不可用时能够展开并手动填写 ID 或 Folder Token。

## Exporter 功能回归

- DOCX、PDF、XLSX 和普通附件能够导出；
- 新版文档内嵌的 PDF 等文件能够下载；
- 同一底层文档出现在知识库多个位置时，不发生内嵌附件键冲突；
- “与主文档同一目录”和“主文档同名子文件夹”两种附件布局均有效；
- 同一文档中的同名附件使用 `（2）`、`（3）` 消歧；
- 有子文档且只有标题、空行、目录或子页面列表的页面会进入疑似导航页清单；
- 三个连续非空正文块、累计约 100 字，或包含表格、图片、附件时，父页面不会进入跳过建议；
- 审核清单默认全部勾选；取消勾选后，对应父页面仍会正常导出；
- 内容分析失败或出现未知文档块时，程序保守地保留该文档并记录警告；
- 长中文、英文和混合文件名不会超过跨平台路径限制；
- 包含 `（`、`）` 的飞书标题导出后仍保留全角括号；
- 第二次导出时，未修改的正文和附件能够根据 `.feishu-export/state.json` 跳过；
- 取消导出并重新启动后，已完成项目仍可继续增量导出；
- 替换附件或正文后，选择“覆盖”能够更新本地文件；
- 权限不足和单项失败会写入 `export-report.csv`，其余项目继续处理；
- 较大知识库的目录与附件扫描进度持续更新，不长期停留在无详细信息的 Pending 状态。

## Exporter 发布包

- Windows x64 / ARM64 ZIP 中的 `FeishuWikiExporter.exe` 为自包含单文件，不附带 PDB 或普通 DLL；
- `linux-x64` 与 `linux-arm64` 同时提供 AppImage 和 Portable TAR.GZ；
- AppImage 赋予执行权限后可以启动并创建 JSON 增量状态；
- 没有 FUSE 时，Portable 版仍可完整解压并启动；
- `linux-musl-x64` 与 `linux-musl-arm64` 只提供 Portable TAR.GZ，并在 Alpine 等 musl 系统上验证；
- 多文件发布包不包含 `e_sqlite3` 原生库。

## 离线知识库与 Reader

- 使用小型知识库生成 `<知识库名>-offline`，确认原文件和层级完整保留；
- DOCX 的常见标题、列表、表格、链接和内嵌图片能够在 Reader 中显示；
- 中文标题搜索、DOCX 正文搜索、摘要和命中高亮正常；
- 标题命中的结果始终排在仅正文命中的结果之前；
- 从搜索结果打开文档后，“返回搜索结果”能够恢复关键词、结果列表和滚动位置；
- PDF、XLSX 和其他附件可以按标题找到并调用系统默认程序打开；
- 再次生成同一离线知识库时，未变化 DOCX 的页面被复用；修改文档后，其页面和搜索结果得到更新；
- 将飞书同级节点排成“文档—导航页—文档”，确认 Reader 保留混排顺序且实际文件名没有增加序号；
- 有正文且有子页面的节点在 Reader 中只显示一次，标题可打开正文，箭头可展开子页面；
- 纯导航页在 Reader 中没有正文入口，但可以展开子页面；
- Reader 能继续打开 `feishu-offline-knowledge` version 1 的旧离线知识库；
- 只调整飞书节点顺序而不修改正文时，增量导出跳过文档，但新生成的 Reader 目录采用新顺序；
- Windows Reader Portable ZIP 解压后可直接运行 `FeishuWikiReader.exe`，不显示额外命令行窗口；
- Fedora / RHEL 系优先安装 RPM，Debian / Ubuntu / Deepin 优先安装 DEB；
- Linux x64 与 ARM64 的 AppImage、DEB、RPM 均至少完成一次对应架构实机测试。
